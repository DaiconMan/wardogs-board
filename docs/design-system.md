# 画面の型（デザインシステム）

WARDOGS の作戦プランナー（`/plan` 系）で共通に使う型。陣営は問わない。
これから足すページ（ゾーン編集、試算ツールなど）はこの型に従う。

**実装は `public/css/` の6枚。**`public/plan.html` に `<style>` は1つも無い
（マークアップだけ。CSS は `<link rel="stylesheet">` 6本で読む）。
ここに書いてあることと実装が食い違ったら、実装のほうが正しいと見なして、この文書を直す。
ビルド工程は足さない（素の HTML + CSS + ES モジュール。束ねる工程を作らない）。

| ファイル | 受け持ち |
|---|---|
| `plan-base.css` | **`:root` のトークン**（§1）・配色・書体・読み物のページの地と板 |
| `plan-board.css` | 盤面に重ねるもの（§8〜§10。配置・地名・塔・円・エリア・カーソル・§15 のライブ） |
| `plan-list.css` | 作戦の一覧の枠の表（§14）とログイン前 |
| `plan-panels.css` | 浮かせた板（§7。パレット・エリア・詳細） |
| `plan-tools.css` | 道具の棚とメニュー（§6）・1択の欄（§16） |
| `plan-narrow.css` | 狭い画面（§12） |

**`public/index.html` はもう作戦ノートではない。**`/plan` へ送るだけの12行で、
CSS も `:root` も本文も持たない（`/` は `public/_redirects` が 302 で `/plan` へ送る）。
トークンはもともとあちらからのコピーだったが、**いまは `plan-base.css` が唯一の持ち主**。

---

## 0. 考え方

この画面は読み物ではなく**道具**で、主役はマップ 1 枚しかない。
そこから 4 つの決めごとが出る。

1. **地図が画面の全部。枠は地図の上に浮かせる。**
   高さを取る header / footer を持たない。重なってもよい。重なったら畳む（§5）。
2. **ゲームから地続きに見せる。** ここはゲームを閉じずに開く道具なので、
   濃いスレートの板・1px の細線・角丸なし・琥珀のアクセントで、ゲームの UI に寄せる（§1）。
3. **同じ見た目のものは同じ種類。** 違う種類（排他の道具 / on-off の表示切り替え /
   取り返しのつかない操作）を同じボタンで並べない。
4. **数値は等幅で組む。** グリッド名・座標・射程・コストは、桁が揃って初めて比べられる。
   この画面でいちばん持ち出されるのは「H8 に FOB」という形の値なので、そこを読みやすくする。

### 一度読めば足りるものを、毎回出さない

2026-10-01 のオーナー指摘（「入り組んでいる・文字が多い・操作性いまいち」）と
同業調査（`docs/research/2026-10-01-ux-benchmark.md`。**上流の内部文書で、
このリポジトリには入っていません**）の結論。
Clutchbase も wardogs.tools も Excalidraw も、**画面に散文を1文字も置いていない。**

常駐をやめたもの（情報は消していない。出す場所を変えただけ）:

| もの | 前 | 今 |
|---|---|---|
| 「未検証」バッジ | ヘッダに常駐 | **その数値のすぐ隣**（縮尺・パレットの射程とコスト・配置の詳細） |
| 「あなたの名前とアイコンも相手に見えます」 | ヘッダに常駐 | **初めて開いた人には出した状態**。一度読んだら `i` の裏（§5） |
| 「◯◯ でログイン中」「共有URLをコピー」「ログアウト」 | ヘッダに3つ | **「自分」のメニュー1枚**に畳む |
| eyebrow「作戦プランナー」 | 盤面のヘッダに常駐 | 盤面では出さない（戻る矢印と作戦名で現在地は足りる） |
| まとまりの見出し「道具」「置く」「見る」 | 棚に3つ | **読み上げ用にだけ残す**（画面には出さない） |
| 太さ3つ | 常に棚にある | **ペンを持っているときだけ**出る |
| 「射程を表示」「地名を表示」 | 棚に常駐 | 「表示」メニューの中 |

### 語彙: 「今回の」「今日の」と書かない（D-046）

この道具は**試合の記録ではなく、パターンごとの準備**を置く場所。作戦は
「マップ × パターン」の単位で作り、同じ枠を何度も見返して育てる。
だから画面の文言も**「今回のゾーン」ではなく「想定するパターン」**と書く。

## 1. 色と書体 — ゲームから地続きに

寄せ先は**ゲーム内 UI の実機スクリーンショット**（オーナー撮影。このリポジトリには含めない）。
読み取ったのは次の4つで、素材（画像・フォント・ロゴ）は一切持ち込まない。

| 参考にした画面 | 取り入れたもの |
|---|---|
| `map-20.png`（フルマップ） | 明るいグレースケールの航空写真を**濃い枠が囲む**／**細い白線**のグリッド／座標とスケール（`1KM` `x73.30` `y97.84`）を**縁に置く**／ラテン文字はコンデンスド |
| `map-31.png`（分隊パネル） | 半透明の濃いスレートの板／**角丸なし**／1px の細線で行を切る／節の頭の `//`（`//分隊`）／`[07]` の角括弧つき数値／**琥珀の主ボタン** |
| `map-33.png`（確認ダイアログ） | **琥珀＝押すと進む**／灰色＝やめる／沈めた面に本文／細い帯の見出し |

### 面と線

| トークン | ライト | ダーク | 役割 |
|---|---|---|---|
| `--paper` | `#E4E7EA` | `#0D1013` | 地図の上の図形の抜き色（`.pm-glyph`）。**読み物のページでは `--void` に差し替える**（下記） |
| `--panel` | `#FFFFFF` | `#171B20` | 地図の上の図形のハロー。**読み物のページでは `#171B20` 固定** |
| `--ink` | `#13181D` | `#E8EDF2` | 本文 |
| `--muted` | `#5A646E` | `#98A3AE` | 補助の文字・罫線 |
| `--line` | `#C2C9D0` | `#2A3138` | 枠線 |
| `--void` | `#0B0E11` | 同左 | **マップの外**（引き切ったときだけ見える） |

もとは作戦ノート（`public/index.html`）の値のコピーだったが、青に寄った無彩色をやめて
中立のスレートにした。**あちらは配信を止めたので、いまこの値を持っているのは
`plan-base.css` だけ**（突き合わせる相手はもう無い）。

**角丸は 0。** `--radius` も `--radius-sm` も `0px`。ゲームの UI が角を丸めない。
影は 2 枚だけ（`--shadow-1` は 1px の段差、`--shadow-2` は地図の上に浮く板の縁）。

### HUD — 地図の上に載る層

**ライトでもダークでも濃い板。** ゲームのフルマップも、明るい航空写真の上に濃い枠が載る。
配色の設定で枠の色が入れ替わると、同じ地図の上で「ゲームと地続き」という関係のほうが崩れる。

| トークン | 値 | 役割 | コントラスト |
|---|---|---|---|
| `--hud` | `rgba(20,24,28,.90)` | 板の面 | — |
| `--hud-raise` | `rgba(44,50,57,.96)` | 板の中のボタン | — |
| `--hud-sunken` | `rgba(0,0,0,.28)` | 板の中の見出し帯・沈めた面 | — |
| `--hud-line` | `rgba(226,234,242,.22)` | 細線（1px） | — |
| `--hud-line-hi` | `rgba(226,234,242,.45)` | 触れたときの細線 | — |
| `--hud-ink` | `#E8EDF2` | 板の上の本文 | **13:1** |
| `--hud-muted` | `#9AA6B2` | 板の上の添え字 | **6.6:1** |
| `--amber` / `--on-amber` | `#C9A227` / `#15140F` | **押すと進む**（1画面に1つ） | **7.8:1** |

板の不透明度は .90。中くらいの地形（`#808080`）の上に重ねても本文で 13:1 出る（AAA）。

### 読み物のページ（一覧・ログイン前）も同じ家族にする

2026-10-01 のオーナー指摘「**画面の前後で配色がかなり違います**」。
D-050 の作り直しが**盤面だけで止まっていた**ので、一覧とログイン前は琥珀のボタンだけ
新しく、地と板は旧デザイン（ライトでは白地）のままだった。

**地図が無い画面なので、盤面と同じ形にはならない。揃えるのは次の4つだけ。**

| 揃えるもの | どうやって |
|---|---|
| 同じ地 | `--paper` を `--void`（`#0B0E11`）にする。**一覧から盤面へ移っても地の色が 1px も変わらない** |
| 同じ板 | `--panel` は `#171B20`。面は3段（地 ＜ 板 ＜ 押せる面 `--hud-raise`）。**書き込む面だけ逆に沈める**（`--hud-sunken`。ゲームの確認ダイアログ `map-33`） |
| 同じ線 | `--line` は `--hud-line-hi` |
| 同じアクセント | 琥珀（`.primary`）と `--blue-bright` |

**ライトでもダークでも濃い地。** HUD と同じ理由で、配色の設定で一覧だけ白地に戻ると
「同じ道具の中で地続き」という関係のほうが崩れる。
ただし**一覧は文字を読む画面**なので、暗くして読めなくなっては本末転倒。実測値:

| | 比 |
|---|---|
| 本文（`--ink` / 板） | **14.7:1** |
| 添え字（`--muted` / 板） | **7.0:1** |
| 枠（`--line` / 板） | **3.9:1** |

**線だけ盤面より一段明るいほうを使う。** 盤面の板は航空写真の上に乗るので `--hud-line`
（.22）でも縁が立つが、平らな濃い地の上では立たない（1.9:1）。ボタンと入力欄の枠は
「押せる・書ける」を見分ける唯一の手掛かりなので、ここは 3:1 を要る。

`e2e/plan-identity.spec.js` がこの4つ（地の色の一致・本文・添え字・枠）を機械で固定している。

**`:root` に `color-scheme:dark` と `scrollbar-color` を置く。**
スクロールバーとキャレットは CSS では塗り切れないので、できるところまでは
こちらで指定し、残りを `color-scheme` に任せる。

**ただし `<select>` をこれに任せるのは失敗した（2026-10-01）。**
オーナーの実機（Windows Chrome）では `color-scheme:dark` が効かず、選択肢の一覧が
**薄いグレー地に薄いグレー文字**になって読めなかった。ポップアップは DOM に存在せず
`npm run shots`（Linux のヘッドレス Chrome）にも写らないので、**壊れていることを
機械でも目でも確かめられなかった。**

→ **`<select>` は使わない。**1択は `.choice`（§16）で出す。
**教訓: ブラウザに描かせる部分を増やさない。確かめられないものは直したと言えない。**

**板の中身の色は、器のところでトークンを差し替えて一括で切り替える。**

```css
body[data-page="board"] > header > *, … {
  --panel:var(--hud-raise); --paper:rgba(0,0,0,.26);
  --ink:var(--hud-ink); --muted:var(--hud-muted); --line:var(--hud-line);
  --blue:var(--blue-bright); --blue-solid:var(--blue-bright); --on-blue:#06121B;
}
```

既存の規則はすべて `var()` で書いてあるので、器の側で意味を差し替えれば中身は自動で濃い板向きになる。
板ごとにボタンや入力欄の色を書き直すと、部品を足すたびに書き漏れる。

### 意味を持つ色は据え置く

`--blue` `--hot` `--red` `--green` `--cursor-1〜8` は**値も意味も変えない。**
地図の上の図形はこの色で読む約束になっている（§8 以降）。

**琥珀（`--amber`）と `--hot`（未検証）はどちらも黄色だが、形で分ける。**
琥珀は**面を塗った主ボタン**（1画面に1つ）、未検証は**細枠の小片＋「未検証」の文字**。
色だけに頼っていない。

### 書体 — 3役

| トークン | 値 | 使う所 |
|---|---|---|
| `--font-ui` | `"Zen Kaku Gothic New"`, system-ui, … | 文章・ラベル・ボタン |
| `--font-display` | `"Saira Condensed"`, … | **ラテン文字と見出しの小文字**。eyebrow・マップ名・ガターの `A`〜`P`・セル名 |
| `--font-data` | `ui-monospace, …`（system stack） | **桁を比べる数値**。座標・射程・コスト・件数 |

ゲームの HUD はラテン文字と数字がコンデンスドの技術書体で組まれている
（`1KM` `x73.30` `BRAVO-1 [07]`）。日本語はふつうのゴシックなので、
**ラテンだけ**コンデンスドに替えると地続きに見える。取得は 1 リクエスト
（Zen Kaku と同じ `<link>` にまとめてある）。

**座標・コスト・射程は等幅のまま。** カーソルを動かすたびに桁が踊ると読めない。
`--font-data` を当てる所には `font-variant-numeric: tabular-nums` も一緒に当てる（`.data`）。

**等幅にしないもの**: 地名（`.co-name`）。人が付けた呼び名で、桁を揃えて比べるものではない。

### 構造の印

ゲームの UI から持ってきた、**線を引く代わりの印**。

- **`//` の eyebrow**（`//道具` `//背景の見せ方`）。`.eyebrow` `.cluster-label` `.menu-head` の `::before`。
  **押せるものには付けない**（読み上げの名前に混ざる）
- ラテン文字の見出しは**大文字＋字送り `.16em`**

### 大きさ（6段だけ。中間値を作らない）

| トークン | px | 使う所 |
|---|---|---|
| `--t-eyebrow` | 10 | まとまりの見出し、未検証の印 |
| `--t-micro` | 11 | バッジ、出典、パレットの meta |
| `--t-small` | 12 | 補助の文字、フォームのラベル、状態表示（盤面） |
| `--t-body` | 13 | ボタン、本文、定義リスト |
| `--t-lead` | 15 | 一覧の題名、読み取りの座標 |
| `--t-head` | 18 | 節の見出し（`.sheet h2`）、寄ったときのセル名 |

### 見出しの階層

- `h1` は **1 ページに 1 つ**。ヘッダの `#title`（＝現在地）だけが使う。
  - 盤面では作戦名。**eyebrow（`#brand`）は出さない**（戻る矢印と作戦名で現在地は足りる）
  - 一覧では「作戦プランナー」
- `h2` は節とパネルの見出し。`h3` は節の中を2つ以上に割るときだけ。`h4` 以下は作らない。

## 3. ボタン

### 種類は4つ

| 種類 | 見た目 | 使う所 |
|---|---|---|
| 既定（`button`） | 面 + 1px の枠 | ほとんど |
| `.primary` | **琥珀（`--amber`）塗り** | **1 画面に 1 つまで**。`作戦を作る` `Discord でログイン` |
| `.quiet` | 枠も面も無し。触れたとき出る | 添え物。`共有URLをコピー` `ログアウト` `閉じる` |
| `.danger` | 文字が `--danger` | 取り返しのつかない操作。**`.quiet` と併せて使う** |

- 最小の当たり判定は **44x44 CSS px**。リンク型の操作（`a.open` `#to-list`）も同じ。
  例外は在室の `i`（`.pres-info`）で、**見た目は 22px・当たり判定だけ `::after` で 44x44 に広げる**
  （粒の列の中に 44px の丸を置くと、人数より印のほうが目立つ）
- フォーカスは `outline:2px solid var(--blue); outline-offset:2px`。**消さない。**
- 無効は `opacity:.45` + `cursor:not-allowed`。

### ラベルは短く、名前は full で持つ

**見える文字を短くし、読み上げ用の名前は `aria-label` に全文で置く。**

| 見える文字 | `aria-label` / `title` |
|---|---|
| `消す` | 消しゴム |
| `地名` | 地名を置く |
| `戻す` | 取り消す |
| `全体` | 全体表示 |

アイコンにはしない。日本語の2文字はアイコンと同じ幅で、意味が確実に伝わる
（同業はアイコンのみだが、あちらは英語で `Pan` `Draw`）。

### 押している状態は2段階

| 段階 | 見た目 | 使う所 |
|---|---|---|
| 強（排他の1組） | `.segmented` の中で塗りつぶし | 移動 / ペン / 消す / 地名 |
| 弱（on-off） | `--blue-soft` の下地 + 内枠 | 建造物、円とマス、射程、地名を表示、背景の選択肢 |

どちらも状態は `aria-pressed` で持つ（色だけに頼らない）。

## 4. 画面の骨格 — 地図が全面、枠は浮く

**ここが 2026-10-01 の作り直しの核。**

以前は `body` が header / main / footer の3段で、枠が**実寸の行**として高さを取っていた
（1920x1080 で合計 133px、390x844 で 210px）。さらに viewBox の縦横比をマップ（正方形）に
合わせていたので、16:9 の画面では左右にレターボックスが出た。

**結果、地図は画面の 42%（390px では 46%）しかなかった。**
しかも 390px ではヘッダが設計書の予算（2段）を破って **3段 137px** になっていた。

```
┌──────────────────────────────────────────────┐
│ [←|作戦名]                     [在室] [自分▾] │ ← header: position:absolute
│                                              │   pointer-events:none
│                                              │
│                  地  図                      │ ← main: position:absolute; inset:0
│              （画面の全部）                   │
│                                        ⊔ 2km │ ← #map-readouts（右の縁）
│                                 x73.30 y97.84│
│ ▸ いま選んでいる道具の説明                     │ ← #status
│ [移動|ペン|消す|地名] 戻す │ 建造物 円とマス │ … │ ← footer: position:absolute
└──────────────────────────────────────────────┘
```

- `body[data-page="board"]` のときだけこの形。`list`（作戦の一覧）と `gate`（ログイン前）は
  読み物なので従来の3段のまま。属性は `app.js` の `setPage()` が1箇所で付ける
- **header / footer 自身は `pointer-events:none`**。中の操作子だけ `auto` に戻す。
  板と板の隙間は**どこでも地図として触れる**（Excalidraw と同じ作法）
- 枠の実寸は JS（`measureChrome()`）が測って `--chrome-top` / `--chrome-bottom` に書き戻す。
  浮かせたパネル・縮尺・座標はその値だけ内側に寄る。**数値の持ち主は app.js 1 箇所**
  - **下は棚（`#rail`）の上端まで**で測る。状態表示まで含めると、文が出るたびに座標表示が飛ぶ

### 既定の視野は「画面を埋める」（§7 の旧判断を捨てた）

旧 §7 にはこう書いてあった。

> 浮かせても地図が隠れないのは、マップが正方形で盤面の左右にレターボックスができるから。

**つまり「パネルを地図に重ねないために、地図を小さいままにしていた」。**
同業は逆で、**全面にして重ね、重なったら畳む**。この判断を捨てる。

| 関数（`viewport.js`） | 意味 | 使う所 |
|---|---|---|
| `coverView(map, ratio)` | **マップが画面を埋める**（余白が1pxも出ない） | **開いた直後** |
| `containView(map, ratio)` | マップ全体が収まる（いちばん引いた状態） | **「全体表示」**、ズームアウトの上限 |

**viewBox の縦横比は、マップではなく盤面（画面）の縦横比に合わせる。**
こうすると `preserveAspectRatio` の meet と slice が一致し、レターボックスが構造的に出なくなる。

実測（`e2e/plan-layout.spec.js` が下限を固定している）:

| 画面 | 前（地図の実寸） | 後 |
|---|---|---|
| 1920x1080 | 938x938 = **42.4%** | **100%** |
| 390x844 | 390x390 = **46.2%** | **100%** |

引き換えに、開いた直後はマップの外周が画面の外にいる（16:9 なら上下、縦長なら左右）。
**「全体表示」1 押しで戻る**ので、これは受け入れる。

## 5. 枠に置くもの

### header — 2枚の板

| 板 | 中身 |
|---|---|
| 左（`.plate`） | `←`（`#to-list`、読み上げ用の文字は残す）｜ `h1#title`（作戦名）＋ `#map-name`（下に小さく）｜ `#read-only`（「見るだけ」の札）｜ `#visibility`（公開設定。畳んだメニュー） |
| 右（`.plate-right`） | `#presence`（在室の粒）｜ `#account`（畳んだメニュー） |

- **左端は必ず戻る導線。** 盤面では**プランの読み込みより先に出す**。失敗した画面を行き止まりにしない
- **人数が増えても高さを変えない。** 在室の粒は `.pres-row` の中で横スクロール（`nowrap`）。
  粒は高さ 22px 固定、注記は広い画面では1行（`nowrap`）。板の幅は `max-width:min(46vw,560px)`
  で頭打ちにする（`flex-basis:0` にすると注記が板の外へはみ出し、明るい航空写真の上に
  素の文字が乗って読めなくなる。実測）
- **`#account` に畳むのは3つ** — 自分の名前（`#who`）・共有URLをコピー・ログアウト。
  畳んだボタンには**人型の線画（`.acct-icon`）と名前（`#account-name`）の2つ**を出す（下記）

### この作戦の公開設定（`#visibility` / `#read-only`）は**左の板**

「この作戦を誰が見られるか」は**作戦の持ち物**なので、作戦名と同じ板に置く。
**作った人にだけ出す**（他の人には `#read-only` の札だけ）。中身は `.choice`（§16）の
3択で、**`<select>` は使わない**（§1）。

**右の板（在室）に混ぜないこと。** 混ぜると、固定幅の札が人の名前と幅を奪い合って
**名前のほうが潰れる** — 下の「上限は名前に置く」の教訓そのもので、
**実測で 390px の `#presence` が 200px → 168px になり e2e が落ちた。**
左の板なら代わりに縮むのは作戦名で、あちらは `max-width:46ch` + ellipsis を持っている。

**書き込めない理由は画面のどこかに必ず出す。** 読専の作戦では道具の棚が押せなく
なるので、理由が無いと「壊れている」に見える。札（`#read-only`）＋ `title` に全文。

### 「見るだけ」のときは、書く道具だけ止める（`setViewOnly`）

`setEditable(false)` は棚のボタンを**全部**止める。あれは「API が不通」＝何もできない
状態のためのもので、読専の作戦には強すぎる。**拡大縮小と「表示」は残す**
（読めるのに読む道具が効かないのでは「読むだけ」が成り立たない）。
`state.editable` は false のままにして、盤面の書き込みと詳細パネルの欄はそれで止める。

### 名前の出し方 — 上限は「名前」に置く。固定の添え字に置かない

2026-10-01 のオーナー指摘「**右上のDって何ですか**」。原因は2つあって、別物だった。

| | 原因 | 直し方 |
|---|---|---|
| `#account` | **意図して頭1文字に切っていた**（`app.js` が `[...name][0]`）。幅も `text-overflow` も無関係で、**中身がそもそも1文字**だった | 中身は名前の全文。**見た目の省略は CSS に任せる**（`max-width` + ellipsis） |
| 在室の粒 | `.pres-chip{max-width:18ch}` の中で、`（あなた）` が `white-space:nowrap` ゆえ min-content 55px を手放さず、`min-width:0` を持つ `.pres-name` だけが潰れていた（実測: 43px → **21px**） | **上限を粒から名前へ移す。** 粒は中身ぶんの幅になり、溢れたら列が横に送る |

**教訓: 幅の上限は「長さが変わるもの」に置く。** 固定の添え字と同じ箱に入れて競わせると、
固定のほうが勝って、可変のほう（＝人の名前）だけが潰れる。

- 畳んだボタンは**人型の線画 ＋ 名前**。アイコンだけだと誰か分からず、名前だけだと
  記号だけの表示名のときに何のボタンか分からない。**両方出す**
- 上限は px ではなく**文字数**（`ch`）。Discord の表示名は日本語も絵文字もありえる

| | 広い画面 | 560px 以下 |
|---|---|---|
| `#account-name` | 14ch（13px。日本語で約7文字） | 8ch |
| `.pres-name` | 14ch（11px。日本語で約7文字） | 10ch（`（あなた）`はこの幅では隠す） |

- **省略しても全文は必ず取り返せる。** DOM の中身は全文のまま（読み上げ）、
  `title` に全文（マウス）、`#account` のメニューの中の `#who` に「◯◯ でログイン中」
- `aria-label` は要素の中身を上書きするので、**`#account > summary` の `aria-label` には
  名前を入れる**（`自分の設定（DAICON）`）。入れないと読み上げから名前が消える

### Discord のアイコン — **色の丸に置き換えず、丸の中身にする**

色は「ペン＝カーソル＝在室の粒＝引いた線」を結ぶ識別子（D-047 / D-068）。
**アイコンに差し替えるとその結びつきが切れる**ので、色の輪で囲む形にする。

| 場所 | 形 | 輪 |
|---|---|---|
| 在室の粒（`.pres-dot`） | 16px の丸。中身は 12px | **有**（2px。本人の色） |
| カーソル（`.cursor-avatar`） | 14px の丸 | **有**（2px。矢印・名前と同じ色） |
| 一覧の作成者（`.by-face`） | 16px の丸 | **無** |

一覧だけ輪を描かないのは、**あちらには部屋が無く、人の色が決まらない**ため
（色は部屋ごとに割り当て、衝突するとずれる）。描くと「一覧では青なのに
カーソルは緑」が起きる。

**出せないときは色の丸に戻す。** ゲスト（`anon:` の人）／`avatar` が NULL の人
／**画像の読み込みが失敗したとき**。壊れた画像のアイコンは出さない。

**粒の寸法はアイコンの有無で変えない。** 変えると、ログイン済みとゲストが
混ざった列（D-072）が凸凹になる。

### 名前の見え方の注記（`.pres-priv`）— 同意に関わる文の置き場所

**常駐はやめた。ただし消していない。**

- **初めてこの道具を開いた人には、開いた時点で出した状態で見せる**
- 一度読んだら畳み、以後は `i`（`.pres-info`）の裏に置く。押せばいつでも読める
- どちらかは `localStorage`（`wardogs.plan.privacy`）が覚える。
  **覚えられないとき（プライベートモード等）は「まだ読んでいない」扱い**にする
  — 迷ったら出すほうに倒す
- D-048 どおり、**誰にも見えていないとき（切断中・離席中）は出さない**

### footer — 棚と、唯一の通知先

- `#status` は**棚のすぐ上**に1行の板。**空なら板ごと消える**（地図の上に空の箱を置かない）
- `#rail` は**道具がある画面だけ**。ログイン前と一覧では畳む

## 6. 道具の棚（`#rail`）

**常に見えているのは5かたまりだけ。**

| まとまり | 中身 | 意味 |
|---|---|---|
| 道具 | `[移動｜ペン｜消す｜地名]` （ペンのときだけ `太さ3`） `戻す` | ポインタが何をするか |
| 置く | `建造物` `円とマス` | どの引き出しを開くか |
| 見る | `− ＋ 全体` `表示 ▾` | どう眺めるか |

### 排他の1組は4つ

`移動 / ペン / 消す / 地名` は**どれも「押すと盤面で何が起きるか」**なので同じ組に入れる。
以前は「地名を置く」だけ別のまとまりにあったが、そうすると
**いま何の道具かが2箇所に分かれて読めない**。

**既定の道具は「移動」**（`DEFAULT_MODE`）。地図を見るつもりのドラッグが描画になってはいけない
（オーナー報告）。並びも押されているものを先頭にして、既定がどれか一目で分かるようにする。
**覚えない**（背景の見せ方と違って localStorage に残さない）。

**「移動」でも、置いてあるものは押せば選べる。** 何の上でも必ずパンになるのは
中ボタンとスペースキーの2つ（`forcesPan`）。

**「消す」は、いま扱っているものに対して効く。** インクを引いているときは線を、
エリアの種類を選んでいるときは塗りを消す（`op='sub'`）。どちらの場合も押下表示にする。

### 従属する設定は文脈で出す

**太さはペンを持っているときだけ出る。** 使わない道具の設定を常に並べておくと、
そのぶん棚が長くなり、狭い画面では本当に要るボタンが画面の外へ押し出される。

### 「表示 ▾」が引き受けるもの

**棚に出すボタンを増やさない。** 中身は3つの見出しに分かれる。

| 見出し | 中身 |
|---|---|
| 背景の見せ方 | `カラー` `モノクロ` `高コントラスト`（排他） |
| 重ねるもの | `射程を表示` `地名を表示`（それぞれ on-off） |
| 地図にあるもの | `ドリルタワー` `陣営スポーン`（同上） |

畳んだときにボタンへ出す値は**背景の設定だけ**（いちばんよく変える）。
「地図にあるもの」はゲームが持っている物で、チームが置いた物とは別の区分。

**メニューは2枚とも同じ作法**（`wireMenu`）。外を押すか Esc で閉じ、**同時に2枚は開かない**。

### 引き出しのボタンは、中で扱うものの名前を名乗る

`円とマス` が開く `#zonepanel` には円の選択・種類の選択・両方の表示 on-off が入る。
この引き出しを「エリア」と呼んでいたときは、円がどこにあるか棚から読めなかった
（オーナー報告: 「円を出すのに導線が長すぎます」）。

**中は3つの一画で、見出しで「誰が決めたものか」を切る。**

1. **コントロールエリア（ゲームが決める）** … 選ぶだけ。手では描けない
2. **ホットゾーン（チームの想定）** … 置く。ゲームが出すものについての想定（§9）
3. **チームの見立て（1km マス）** … 塗る

**円が2つとも上に来る**（棚の名前が「円とマス」なので、円を探す人は必ずここを開ける）。

### まとまりの見出しは画面に出さない

`.cluster-label` は**読み上げのためだけ**に残し（`aria-labelledby` の参照先）、
画面からは外す（1px に潰す）。「道具」「置く」「見る」は一度読めば足りる。
仕切りは `.cluster + .cluster` の `border-left` 1本。

## 7. 浮かせる板（引き出し3枚）

役割が違うので見た目も分ける。同じ箱にしない。

| | パレット `#palette` | エリア `#zonepanel` | 選んだものの詳細 `#placement-detail` |
|---|---|---|---|
| 役 | **引き出し**。ここから選んで盤面に足す | 引き出し（同上） | **検視台**。いま選んでいる 1 件について語る |
| 位置 | 左、枠の内側いっぱい | 左、中身のぶんだけ | 右上 |
| 幅 | 292px | 292px | 300px |
| 印 | 見出しが帯（沈めた面、sticky） | 同左 | **左端 3px が `--blue`** |

- **どれも `position:absolute` で、`--chrome-top` / `--chrome-bottom` のぶんだけ内側に寄る。**
  枠と喧嘩させない
- **地図に重なってよい。重なったら畳む。** 広い画面ではパレットを常設し、
  狭い画面では項目を選んだ時点で畳む（`pickItem` / `setZoneKind`）
- **左の引き出しは同時に 1 枚しか開かない**（`setPaletteOpen` / `setZonePanelOpen` が互いを閉じる）
- **検視台は 1 枚しか作らない。** 種類ごとにパネルを増やさず中身を差し替える

### 中身がはみ出したら、切らずにスクロールさせる

**縦の flex の入れ物に子を積むときは、子に `flex:none` を書く。**
縦の flex の子は既定で縮み、`overflow:hidden` を持つ子は自動の下限も効かないので
0 まで潰れて中身が切り落とされる（実測: 374px の一覧が 43px に潰れた）。
`#palette > *` と `#placement-detail > *` に書いてある。

### パレットは広い画面では常設

- **1024px 以上**: 既定で開いた状態で始まる（`PALETTE_ALWAYS_W`）
- **1024px 未満**: 畳んだ状態で始まる
- **常設でも「閉じる」で畳める。** 自分でボタンを押した開閉だけ `localStorage` に覚える

### 注記（`.note`）

**未検証の数値を確定値のように見せない**ための注意書き（D-026）。
`--hot` の縦線 3px + 薄い下地。個々の項目には `.unv`（未検証の印）を必ず付ける。

## 8. 盤面に重ねるもの（読み取り・縮尺・セル名）

### 縮尺と座標は同じ縁に縦に積む（`#map-readouts`）

ゲームのフルマップ（`map-20`）も `1KM` と `x73.30 / y97.84` を**右の縁にまとめている**。
別々の隅に置くと、枠が浮いた今は棚とぶつかる。入れ物を1つにすれば
「同じ隅に2つ置かない」は flex が保証する。

| | 広い画面 | 560px 以下 |
|---|---|---|
| `#map-readouts` | **右下**（棚の上） | **右上**（下は詳細パネルが占める） |

### 「未検証」はここに出す

マップの一辺（= 縮尺の根拠）が未確認だという話なので、**縮尺のすぐ隣**に置く。
D-026「未検証の数値を確定値のように見せない」は維持。**出す場所だけ変えた。**
印は `--hot` の細枠 + 「未検証」の文字（色だけに頼らない）＋ `title` に理由。

同じ考えで、射程とコストの未検証は**パレットの各項目**と**配置の詳細**に出る。

### 座標が主役、セル名は補助（`#readout`）

`#readout` はカーソルの下の**ゲーム内座標**（`x78.67 y71.62`。1単位 = 100m）と
**セル名**（`H8`）を出す。**大きく出すのは座標のほう。**

1. **ゲームはセル名を表示しない。** フルマップの軸に出るのは km の数字だけ。
   **ゲーム画面と突き合わせて確かめられるのは座標だけ**
2. セル名は**ガターに常時出ている**

- 等幅（`--font-data`）と `tabular-nums` は維持する。桁が揃っていないと見比べられない
- 並べ替え（CSS の `order`）は使わない。**DOM の順＝見た目の順＝読み上げの順**
- `.paint`（「3×2 = 6マス」）だけは先頭に出す

**座標を持ち出す操作（クリップボード）**

| 操作 | 割り当て |
|---|---|
| 左ボタン クリック／ドラッグ | 置く・選ぶ／パン・移動・塗り（D-028） |
| 中ボタン・スペース | パン |
| ホイール | ズーム |
| **右ボタン（指なら長押し）** | **その地点の座標をコピー** |
| **`c`（修飾キー無し）** | 同じ |

コピーする前に**座標表示を今の位置に合わせる**（見えている値とコピーする値を必ず同じにする）。

### セル名はガターに出す（地図の上に文字を置かない）

1km セル（A1〜P16）の呼び名は、**列（A〜P）を上端の外、行（1〜16）を左端の外**に出す。
ゲームのフルマップと同じ形で、**濃い下地（`rgba(12,15,18,.55)`）に白い細線と白い文字**。
`#gutter-cols` / `#gutter-rows` の 2 本の帯で、**SVG ではなく HTML**。

- **地図の上に文字を撒かない。** 以前は 256 個の `<text>` を常時出していた
- 帯は地図の縁に沿う。縁が画面の外に出たら**盤面の縁で止める**
  （既定の視野では外周が画面の外なので、ふだんは盤面の縁にいる）
- **見出しの位置はずらさない。** 詰まるときは **2 つおき・4 つおきと倍々で間引く**
- 併用: **視野が 2000m 未満のときだけ**、真ん中が見えているセルの名前を地図の上に薄く出す
  （`centerCells`。構造的に 4 個以下）

### 縮尺（`#scalebar`）

きりのいい距離（100m / 200m / 500m / 1km …）を選び、**バーの長さのほうを伸縮させる**。

- **倍率（「×2.5」）は出さない。** 作戦で持ち出されるのは距離であって倍率ではない
- `role="img"` + `aria-label="縮尺 500 m"` で 1 つの情報として読ませる
- バーは上端の無い枠（⊔）

### 地名（`#callouts`）

**「地図に元からある情報」であって「置いた物」ではない。**

| | 配置 `.pm` | 地名 `.co` |
|---|---|---|
| 形 | 四角 / 三角 / 丸 / ピン | **小さな点**（r 3.5px）だけ |
| 色 | 種別の色 | **無彩色** |
| 文字 | 形の真下、11px | 点の右、12px |
| 当たり判定 | 形だけ | **点と名前の両方** |

**視野が 4000m より広いときは名前を伏せ、点だけにする**（`CALLOUT_NAME_VIEW_M`）。
上限 200 件とセットで決めてある。選んでいるものとカーソルの下だけは広くても名前を出す。

### 他の人のカーソル（`#cursor-layer`）— Phase R1

**「同時に同じ画面を見ながら」の本体。** VC で「ここ」と言ったときに、相手の画面でも
同じ地点が指されている状態を作る（D-047 の P0-1）。

- **いちばん上の層。** 他人が指している場所が自分の置いた物の下に隠れると「ここ」が
  伝わらない。盤面に重ねるものの中で唯一、配置（`#placements`）より上に置く
- **押せない**（`pointer-events:none`）。他人のカーソルが自分の操作を奪わない
- **マップ座標系に置く。** 送り合うのは画面 px ではなく**マップのメートル座標（整数）**で、
  各自のズームとパンが違っても同じ地点を指す。パンとズームには層ごと自動で追従する
- 大きさは**逆スケール**でズームに依らず一定（マーカー・地名・塔と同じ `markerScale()`。
  更新も `applyView()` に相乗りしていて、専用の経路を持たない）
- **名前を常に出す。** 色は本人の色（`--cursor-1`〜`8`、在室の粒と同じ番号）だが、
  8色を超えると色相が重なる。D-047 は「塗り2種で16通り」と決めてあるが**R1 では
  実装していない**ので、重なったときに誰かを判る手段は名前だけ
- **滑らかさは CSS に任せる**（`transition: transform 100ms linear` の1行）。
  JS で補間すると 20人 × 60fps の rAF を回すことになる。
  `prefers-reduced-motion` では補間を切る
- **自分の「タブ」のカーソルは描かない**（OS のポインタと二重になる）。外す鍵は
  人（Discord ID）ではなく**接続**（サーバが接続時に1通だけ渡す `{"t":"you","k":...}`）。
  同じ人が2枚開いていればポインタは2つあるので、**もう片方のタブのカーソルは出る**
  （人で外していた頃は、2枚開いた人の画面から1本も出なかった。2026-10-02 のオーナー報告）

**消える条件**（どれか1つで消える）

| | いつ |
|---|---|
| 盤面の外へ出た | 棚のボタンなど**操作子の上**に来たとき。`#board` はビューポート全面で、枠は `pointer-events:none` なので「板と板の隙間」は地図のまま（消さない） |
| タブを裏に回した | `document.hidden` の間は送らない |
| 切れた | サーバが配るスナップショットから外れる |
| 3秒更新が無い | 切断の取りこぼし対策（`CURSOR_TTL_MS`） |

## 9. マップが持っている物（`#towers` / `#spawns` / `#zone-preset`）

**ゲームが持っている物**と**チームが置いた物**は、見た目で必ず分ける。

| | 置いた物 `.pm` `.co` | マップが持っている物 `.tw` `.sp` `.zp` |
|---|---|---|
| 塗り | **塗りつぶす** | **塗らない**（塔は線だけ。スポーン 14%、円 7%） |
| 色 | 種別・作者の色 | 塔と円は無彩色、スポーンは陣営の3色 |
| 当たり判定 | **ある** | **無い**（`pointer-events:none`） |
| 大きさ | 画面固定 | 塔は画面固定、**スポーンと円は実寸** |

**「触れない」が一番効く区別。**

- 塔の形は**脚2本・接地線・筋交いの線画**で、座標は**足元**
- 塔の名前は**視野 2000m 以下**でだけ出す。スポーンの陣営名は**常時**
- 出典データの色（`#d86666` など）は**持ち込まない**

### コントロールエリアの円（`#zone-preset`）

ゲームはマップごとに 3〜4 個の固定プリセットを持ち、試合開始時に1個を選ぶ。
**選ばれた円の中のドリルタワーがその試合の対象**になる。

**いちばん大事なのは、下のエリア塗り（`#areas`）と混同させないこと。**

| | エリア塗り `#areas` | コントロールエリアの円 `#zone-preset` |
|---|---|---|
| 形 | 1km セルの集合（矩形） | **実寸の円**（半径 500m） |
| 描き方 | パターンで塗る | **太い線**＋7% の面 |
| 色 | 種別ごと | **無彩色** |
| 作る人 | 誰でも | **admin だけ** |

**ゲームが決める語は、ゲームが決めたものにしか使わない。**

- **半径は実寸で描く。** 中心に**十字**。**破線は「まだ保存していない」の印**
- **パターンを選んだら、円の外のドリルタワーは出さない**（オーナー指示 2026-10-01。
  「有効のものだけ表示でお願いしたいです」）。**選んでいない間は全部出す**
  — どれが対象か決まらないので隠す根拠が無い。その理由も `#zone-preset-info` に書く。
  ゲーム内は無効な塔を破線で出すが（D-055）、**盤面は作戦を練る場であって
  ゲーム画面の再現ではない**
- **円の中のタワーは、色だけでなく形も変える**（足元に塗りつぶした丸）
- 対象が何本かは**その場で幾何から出す**（DB に持たない）。
  **縁ちょうど（距離 = 半径）は「中」に数える**
- **まだパターンを選んでいないことは、引き出しを開けなくても分かるようにする**
  （`円とマス` に `data-unset="true"` で `--hot` の点）

### ホットゾーンの円（`#hotzones`）— **置いた物**だが実寸で描く

**中に入ると人数が2倍に数えられる**（D-052）。半径 85m の小さい円を押さえるだけで
兵力が倍になるので、**これは作戦の核心**。時間で動き、ドリルリグで引き寄せられるため、
盤面に置くのは**チームの想定**（「ここに来たらこう」「ここへ引き寄せる」）。

実体は**配置（`placements`）**で、置く・動かす・消すは他の配置とまったく同じ作法。
円だけを `#hotzones` に実寸（メートル）で描く。
**`#ranges` と別の層にする**（「射程を表示」で一緒に消えてはいけない。射程ではない）。

**いちばん大事なのは、コントロールエリアの円と見間違えないこと。**
寄れば画面上の大きさは同じになるので、**大きさ以外の軸でも分ける**。

| | コントロールエリア `.zp` | ホットゾーン `.hz` |
|---|---|---|
| 半径 | **500m**（Ozeti 550m） | **85m**（未検証） |
| 色 | **無彩色** | **`--hot`**（ゲームの黄色） |
| 線 | **実線** | **破線**（動くもの・想定） |
| 中心 | 触れない十字 | **掴めるピン**（字は `倍`） |
| 誰のものか | ゲームが決めた位置 | チームの想定 |

- **「人数2倍」は3箇所で言う。** 項目名（`ホットゾーン（人数2倍）`）／置いた直後の
  `#status`／詳細の「効果」の行。**円を見ただけでは効果が分からない**ため
- 円に添える札（`人数×2`）は**寄ったときだけ**（視野 4000m 以下）。
  16km 四方では円が数 px なので、札だけが地図に浮く（§8）
- **半径が未検証であることは、カタログの「未検証」バッジではなく注記で言う。**
  85m はカタログの列ではなくコード側の定数（`HOTZONE_RADIUS_M`）で、
  `catalog_items` には測定値を入れていない
- 入り口は**「円とマス」の3つ目の一画**（円を探す人はこの引き出しを開ける。D-049）。
  パレットの「試合の要素」の先頭にも同じものが並ぶ。**どちらから選んでも2手**

## 10. エリア（1km セルの塗り）

自陣・敵陣・中立・最重要・危険予測を、**ゲーム内と同じ 1km セルの集合**として塗る。

- **層は「地図の上・グリッドの下」**
- **当たり判定を持たない**（どのセルかは座標の計算で決める）
- **色 5 種と塗り方 5 種の二重符号化**

| 種類 | 色 | 塗り方 | 縁 | 意味 |
|---|---|---|---|---|
| 自陣 `own` | `--blue` | ベタ（14%） | 実線 | 味方の勢力圏 |
| 敵陣 `enemy` | `--red` | 斜線 | 実線 | 敵の勢力圏 |
| 中立 `neutral` | `--muted` | **塗らない** | **破線** | どちらでもない |
| 最重要 `key` | `--green` | 点描 | 実線 | 優先して取る／守る所 |
| 危険予測 `risk` | `--hot` | 格子 | 実線 | 撃ち合いになりそう・近づくと危ない所 |

**上限は 6 種だが 5 種で止めてある。**

- **縁は外周だけ引く**（`non-scaling-stroke` で画面固定）
- **`<pattern>` は自動では画面固定にならない。** タイルの一辺を
  `PATTERN_PX(8) × metersPerPx()` に毎回書き換える（`applyView`）
- **種類名は視野が 2000m より広いときだけ**出す

### 塗る操作（ドラッグを許す唯一の場所）

D-028 が禁じたのは「ドラッグで取り消し困難な複数オブジェクトができること」。
エリアは (1) 押した瞬間からプレビューと「3×2 = 6マス」が出る、
(2) **1 ジェスチャ = 1 行**（「取り消す」1 回で完全に戻る）ので抵触しない。

## 12. 狭い画面（560px 以下）

枠は浮いているので、**狭くなっても地図の面積は減らない**（100% のまま）。
削るのは枠が覆う量。

- 戻るリンクは矢印だけ（読み上げ用の文字は 1px に潰して**残す**）
- `#rail` は `flex-wrap:nowrap; overflow-x:auto` の 1 段
  - **先頭は「道具」のまとまり。** 以前は `order` で「置く」を先頭にしていたが、
    そのせいで**初期状態で選ばれている「移動」が画面の外**に出て、
    いま何の道具かが最初の画面で読めなかった（調査 §4.2-4）。
    ラベルを短くしたので、390px でも「移動／ペン／消す／地名／戻す／建造物」まで入る
  - `scroll-snap-type:x proximity` + `scroll-padding-left:var(--s1)` で
    **まとまりの境目に止める**（半分のボタンは「壊れている」に見える）。
    `scroll-padding` が無いと、棚の内側の余白ぶん `scrollLeft` が 4px になり
    「送っていない」状態が作れない
  - **まだ送れる向きの端は、`mask-image` で実際に薄くして消す**（`#rail[data-overflow]`）。
    幅は 24px。40px にするとボタン1つぶんが丸ごと薄くなって「壊れている」に見える
  - **横スクロールの入れ物は、はみ出した子を切り落とす。** 狭い画面ではメニューを
    浮かせず、棚の続きとして横に開く（`.menu-body{position:static}`）
- **引き出しと検視台で画面を半分ずつ使う**（パレットは `--chrome-top` の下から 48%、
  詳細は 52% から `--chrome-bottom` の上まで）。枠が浮いたぶん板が伸びやすくなり、
  実機で「車輌」の見出しが詳細パネルに隠れて押せなくなった。境目を決め打ちにする
- `#map-readouts` は上へ逃がす（右上。ガターの帯ぶんだけ内側に寄る）
- 注記（`.pres-priv`）はこの幅だけ折り返しを許す（在室が自分の行を持つため）

## 14. 作戦の一覧（`main.create`）— **枠の表**

作戦は「マップ × パターン」の単位で、総数は 9〜12 件で頭打ちになる（D-046）。
**作るのは 9〜12 回で終わり、開くのは試合のたび。** だから一覧は**枠の表**にする。

オーナー指摘（2026-10-01）: 「これでいいとおもってます？」
それまでは左に大きく作成フォーム、右に小さく一覧で主従が逆、しかも
**まだ作っていない枠が画面に存在しなかった**ので、9つのうち何が埋まっていて
何が空いているかが読めなかった。

- **空いている枠も最初から並べる**（`.s-cells` > `.s-cell`）。
  **埋まっている枠は実線で面あり、空の枠は破線で面なし。**
  「まだ決まっていない＝破線」は `.pattern.none` と同じ約束で、色を足さずに形で出す
- **枠の数を固定値で持たない。** `GET /api/maps` が返す `presets` の行数だけ描く
  （プリセットは今後も増減する。画面にもコードにも「9」と書かない）
- 区画の順はマップ名順、枠の順はパターンの `sort_order` 順。
  **更新の新しい順にしない**（試合中は同じ作戦がいつも同じ場所にいることが速さ）
- 区画の見出しに **`埋まった数 / 枠の数`**、表の上に1行で全体の進み具合
- **1枠1作戦を前提にしない。** 同じ枠に積む（「初動」「巻き返し」）
- **パターン未設定の作戦は別区画**（`.s-extra`）。枠には数えないが隠さない。
  `.s-cell` と同じクラスにしないこと（枠の数が狂う）
- **常設の作成フォームを置かない。** 空の枠を押すと、その枠の中に題名の欄だけが開く。
  **マップもパターンも押した枠が決める**ので、選ぶ欄が無い
- 「開いたことがある作戦」は**最後に開いた順**なので枠に分けない。行がマップとパターンを名乗る
- 「**公開されている作戦**」（`#public-list`）も枠に分けない。更新の新しい順で、
  行がマップ・パターン・作成者・**書き込めるか**（`見るだけ` / `書き込める`）を名乗る。
  開いてから棚が押せないことに気づくのでは「壊れている」に見えるので、**一覧の行で先に言う**
  - **訪問済みの作戦はこの節から落とす**（サーバは両方に返す）。同じ行が2つの節に出ると、
    どちらを押しても同じ所に行くのに「別のものかもしれない」と読ませてしまう。
    落とすのは公開の節のほうで、訪問履歴は残す（URL を無くした人の辿り先を減らさない）
- **0件の節は出さない。** 空の見出しだけが並ぶ画面にしない（「開いたことがある」と同じ）
- **配色は盤面と同じ家族**（§1「読み物のページも同じ家族にする」）。地は `--void`、
  枠は `--panel`、`開く` は一段持ち上げた面、入力欄は一段沈めた面

## 15. まだ確定していないもの（Phase R2）— 運搬とライブ描画

**§8 の「他の人のカーソル」の続き。** R1 では**カーソルだけ**が動いていて、
物と線は「保存されてから」しか相手に出なかった。VC で「これ、ここに動かすわ」と
言っている数秒が相手の画面では**何も起きていない時間**になり、落とした瞬間に瞬間移動していた。

**この節のものは全部「一時的な見せ物」で、3つの性質を共有する。**

| | |
|---|---|
| **D1 には何も書かない** | 確定値は従来どおり「本人が保存 → `chg` → 全員が GET」で来る。**D1 が唯一の真実** |
| **押せない** | まだ保存されていないので、消しゴムが掴むと「消したのに消えない」になる |
| **カーソルが消えるのと同じ瞬間に消える** | 寿命の管理は `board/live.js` 1本（`dropLive`）。中断・盤面から出た・**タブが落ちた**の3つすべて |

3つ目を別経路にすると、**落ちた人の物が動かされた位置のまま残り、
実際には動いていない盤面を全員が見ながら作戦を立てる**ことになる（カーソルが残るより害が大きい）。

**層は分けない。既にある図形の見た目を変えるだけ。** 新しい層も新しい図形も足さない
（運搬は `#placements` / `#callouts` のまま、線は `#live-ink` の1層）。

### 15a. 運んでいる最中のもの（`[data-carry]`）

**運んでいる人のカーソル色で縁取る。**

| | 値 |
|---|---|
| 印 | ハロー（`.pm-halo` / `.co-halo`）の線の色を `--carry` にする |
| 色 | **運んでいる人の色**（`--cursor-1`〜`8`。`board/carry.js` が `--carry` に入れる） |
| 太さ | 配置は 8、地名は 7（`stroke-opacity:1`） |
| 名前 | **出さない。** その人のカーソルがすぐ隣にあるので色だけで伝わる |

- **選択の青（`.sel`）より後に置く。** 同じ詳細度なので後が勝ち、
  **選んでいることより「いま動いている」を先に見せる**（選択は右のパネルにも出ている）
- **滑らかさは CSS に任せる**（`transition: transform var(--cursor-tween, 100ms) linear`）。
  カーソルと同じ理由・同じ値で、長さは `board/cursor.js` が在室の人数から入れる。
  **運ばれている間だけ掛ける**（常時掛けると自分のドラッグが遅れて付いてくる）
- **`cursor` は変えない**（＝掴めるままに見せる）。同じ物を2人が触ったときは
  **手元の操作が勝つ**ので、掴めないように見せるのは嘘になる
- **位置は絵だけが動く。** 保存された座標（`obj.x_m`）は触らず、`obj.carry` という
  一時の項目だけを置く

### 15b. 引いている最中の線（`#live-ink path[data-live]`）

**確定した線と見分けがつく状態にする。**

| | 確定した線 | 引いている最中 |
|---|---|---|
| 不透明度 | 1 | **`.55`** |
| 線 | 実線 | **破線**（`stroke-dasharray:9 7`） |
| 色と太さ | 本人のペン | **同じ**（確定した瞬間に色も太さも変わらない） |
| 描き方 | `toSmoothPath` | **同じ**（違う描き方だと確定した瞬間に形がわずかに変わる） |
| 当たり判定 | ある | **無い**（`#live-ink{pointer-events:none}`） |

- **薄さと破線の2つで出す。** 色だけに頼らない（§1 と同じ約束）
- 破線の刻みは `vector-effect:non-scaling-stroke` が効いているので**画面基準**で一定。
  寄っても引いても同じ見た目で読める
- **`prefers-reduced-motion` でも破線は残す。** これは動きではなく「未確定」の印（§13 の例外）

### 消えるときに跳ね返らせない

**離した瞬間に片付けない。取り直しが来るなら着地まで預ける**（`board/live.js`）。

確定した値が届くまでに `chg` → 300ms デバウンス → GET で**実測 400ms 前後**かかる。
その間に先に片付けると、運搬は**元の位置へ跳ね返ってから新しい位置へ飛び**、
線は**一瞬消えてから本物が出る**。どちらも「動いていない」より悪い。

## 17. 新しいページを足すとき

1. `app.js` の `setPage()` で `data-page` を決める。地図があるなら `board`、
   読み物なら独自の値にして3段のレイアウトを使う。
